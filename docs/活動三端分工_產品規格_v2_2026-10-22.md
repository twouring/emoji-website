# 活動三端分工產品規格 v2

版本：2026-10-22 定案版｜取代 `App活動管理_產品規格_2026-10-22.md` 的「App 只做常用、進階外連 /organizer」方案
決策來源：KK 2026-10-22 指示；§9 決策 KK 2026-10-22 08:02 回覆定案（v2.1）

## 1. 結論

| 端 | 網域 | 角色 | 活動相關功能 |
|---|---|---|---|
| Admin | admin.emoji.tw | 只給言文字管理員 | 全部活動的審核、管理、退款、結算、稅金、強制下架。**不再提供活動主入口 `/organizer`** |
| Website | www.emoji.tw | 只負責展示 | 活動列表、活動詳情、SEO、分享、行事曆訂閱。**沒有報名表**；所有「報名」按鈕都跳到 App |
| App | app.emoji.tw | 會員 | ① 報名、付款、票券、取消、轉票、回饋 ② 主辦：建立、上架、管理活動、簽到 |

App 的同一個帳號同時是參加者和主辦人，不另外設「活動主帳號」。

## 2. 現況盤點（依程式，2026-10-22）

| 項目 | 現況 | 搬移影響 |
|---|---|---|
| 報名表 | 在官網 `public/events.html`（666 行），內含票種、報名表、團體報名、加購、錢包驗證、優惠碼、收據、轉票、通知偏好、回饋 | 要在 App 重做一套報名流程，**這是最大的工程量** |
| 免登入報名 | 訪客填姓名＋Email 就能報名（`/api/events/:id/register` 用 `optionalAuth`） | App 要保留免登入報名，否則轉換率會掉（見決策 2） |
| 活動主後台 | `/organizer` 與 `/admin` 共用 `admin.html`，主辦人看到的是桌面後台 | 要在 App 做主辦功能；`admin.html` 移除 organizer 模式 |
| 建立活動 | 一般會員只能送「場地申請」，送出時建草稿活動；直接建立限平台管理員（`server.js` L2726） | 開放會員建立，需要放寬權限（見決策 1） |
| API | 報名、名單、簽到、通知、票種、報名表等 API 都已存在，並依角色擋權限 | **後端大致沿用**，主要改連結與權限 |

## 3. 網址規則

- App 活動詳情：`app.emoji.tw/e/<slug>`；主辦：`app.emoji.tw/host`、`/host/<eventId>`。
- 官網的報名按鈕：`app.emoji.tw/e/<slug>?<原參數>#<原 hash>`。必須**原樣帶過去**的參數：`tt`、`ticket_id`、`coupon`、`coupon_code`、`unlock_code`、`ref`、`utm_*`、`gclid`、`fbclid`、`li_fat_id`、`lang`，以及 `#invite=`。
- 舊連結相容：官網 `/events/<slug>` 繼續當展示頁；如果網址帶有報名用的參數（`tt`、`unlock_code`、`coupon`、`#invite`），就自動轉到 App。`/organizer/*` 一律 302 到 `app.emoji.tw/host/*`。`/events/result/*` 轉到 App 的結果頁。
- `APP_HOST_OWN` 需要放行 `/e/`、`/host`。

## 4. 使用流程

### 4.1 參加者：從官網到完成報名

1. 官網活動頁 → 點「報名」（手機底部固定 CTA 也一樣）→ 開 App `/e/<slug>`。
2. App 顯示活動摘要＋報名表。**未登入也能填**：姓名、Email、題目、票種。
3. 送出 → 免費票直接完成；付費票轉 Stripe → 回到 App 結果頁。
4. 完成頁：顯示票券 QR；未登入者提示「用這個 Email 登入 App，隨時查看票券」，並寄 Email 登入連結。
5. 已安裝 PWA 的使用者在手機上會直接進 App；沒安裝的就以網頁開啟 App，不強迫安裝。

### 4.2 主辦人：建立到上架

1. App「活動」分頁 → 「我主辦的」→ 「＋ 建立活動」。
2. 3 步建立：①名稱、封面、介紹 ②時間、空間（言文字場地內選空間）、公開／私人 ③售票方式與票種（見 4.4）。畫面即時顯示場地費試算（見 4.6）。
3. 存成草稿 → 預覽（就是官網展示頁的樣子）→ 「送出上架」。
4. **一律送審**（決策 1、4）：送出上架＝建立場地申請，沿用現有 `event_applications` 審核流程；審核通過才公開。
5. 私人活動：送出後付場地費（見 4.6），付款後才進入審核（沿用現有「訂金付款後才可通過」的檢查，金額改為場地費）。

### 4.3 主辦人：管理一場活動（App `/host/<id>`）

分頁式，手機一次只看一件事：

| 分頁 | 內容 | 階段 |
|---|---|---|
| 總覽 | 狀態、報名數／名額、今日待辦、分享連結與 QR | P1 |
| 來賓 | 搜尋、篩選、狀態變更、手動簽到／撤銷、匯出 CSV | P1 |
| 簽到 | 相機掃描（沿用 App 既有 `BarcodeDetector` 掃碼）、快速模式 | P1 |
| 通知 | 群發、排程、選對象 | P1 |
| 編輯 | 基本資料、封面、內容、地點 | P1 |
| 票種 | 新增／停用、價格、名額、銷售期間、隱藏票 | P1 |
| 報名表 | 題目增刪、排序、必填 | P2 |
| 團隊 | 邀請共同管理、簽到人員 | P2 |
| 優惠碼、數據、票款紀錄、回饋、複製活動 | — | P2 |
| 稅金、退款、結算 | 不在 App，只在 Admin | — |
| 審核前後設定、API／Webhook、錢包／Token 票、Meet／Zoom、多語翻譯 | 進階 | P3（P3 完成前，主辦人可請言文字管理員在 Admin 代設） |

### 4.4 售票方式：言文字售票或外部售票平台（建立活動步驟 ③）

主辦人在步驟 ③ 二選一，之後可以改（有效報名為 0 時才能改，見例外）：

| 選項 | 行為 | 現況 |
|---|---|---|
| **透過言文字售票** | 票種、名額、付款、QR 票券、簽到都在 App；言文字統一收款 | 已有（`registration_mode='native'`） |
| **前往其他售票平台** | 填外部報名網址；官網與 App 的「報名」按鈕直接開該網址並帶上 `utm_*`；App 只展示活動，不收名單也不出票 | 已有（`registration_mode='external'`、`registration_url`，`server.js` L2752）；目前只在 Admin 能設 |

- 外部網址只接受 `https://`，存之前用 `safeHttpUrl` 驗證；平台名稱依網域顯示（例如「前往 KKTIX 報名」），認不得的網域就顯示「前往報名網站」。
- 外部售票的活動：App 主辦頁只顯示「總覽、編輯、通知追蹤者」，隱藏來賓、簽到、票種分頁；數據只算「點擊前往報名」次數，不算報名數。
- 可選擇開啟「言文字簽到」：主辦人匯入外部平台匯出的名單 CSV（沿用 `/guests/import`，只有姓名、Email），就能在現場用 App 簽到。P2 再做。

### 4.5 從其他活動平台匯入活動

入口：「＋ 建立活動」第一頁上方「從其他平台匯入」。

1. 主辦人貼上活動網址。
2. 伺服器抓該頁，依序讀 schema.org `Event` JSON-LD → Open Graph（`og:title`、`og:description`、`og:image`）→ 頁面標題，取出：名稱、介紹、開始／結束時間、地點、封面圖、主辦單位。
3. 結果帶進 3 步建立表單，每個欄位標示「已匯入」，主辦人逐欄確認、補齊缺的（時間、地點最常缺）。
4. 售票方式預設「前往其他售票平台」，報名網址＝原網址；主辦人可以改成言文字售票。
5. 存成草稿，接上 4.2 的上架流程（同樣走審核）。

規則：
- 只匯入**一次性複製**，不會持續同步；原平台之後改時間，言文字這邊不會自動更新（P3 再評估同步）。
- 封面圖下載後存到言文字自己的儲存空間，不熱連結原網站。
- 同一個原網址重複匯入時提示「你已匯入過這場活動」並連到該草稿。
- 送出前要勾選「我是這場活動的主辦方或已取得授權」，避免搬別人的活動。
- 支援平台以實測為準：Luma、Accupass 活動通、KKTIX、Eventbrite、Meetup、Facebook 活動。**哪些平台頁面有完整 JSON-LD 尚未驗證**；抓不到資料的平台退回「只帶網址＋手動填寫」，不顯示假資料。Facebook 活動通常需要登入才看得到，預期無法匯入。
- 安全：伺服器抓網址要防 SSRF（只允許 https、擋內網 IP 與 metadata 位址、限 5 秒與 2MB、不跟隨轉址到內網），每帳號每小時限 20 次。

### 4.6 場地費（KK 2026-10-22 定案）

**公開活動**：每人 NT$150，附茶飲一杯。
- 言文字售票：每張票自動加一行「場地茶飲費 NT$150」，由參加者付款時一起付；免費活動在報名頁顯示「現場茶飲費 NT$150」，改成報名時線上付款。
- 外部售票：審核通過後，主辦人依預估人數先付；當天實到人數超過的部分，在櫃檯每人補 NT$150。
- 場地茶飲費不撥給主辦人，也不計入 10% 手續費的基數。

**私人活動**：依人數級距定額，可全額折抵當場餐飲（含酒水、不折現，沿用母檔包場規則）。

| 空間 | 人數 | 場地費 |
|---|---|---|
| 三樓 等等空間共享活動區 | 1–10 人 | NT$5,000 |
| 三樓 | 11–20 人 | NT$10,000 |
| 三樓 | 21–30 人 | NT$15,000 |
| 三樓 | 31–40 人 | NT$20,000 |
| 三樓 | 41 人以上 | 每人 NT$500（人數 × 500，例：50 人＝25,000） |
| 二樓 交誼廳 | 至多 10 人 | NT$10,000 |
| 一樓 在咖啡／三點水 包場 | 至多 50 人 | NT$30,000 |

- 主辦人填預估人數後，系統自動算出金額；二樓超過 10 人不能送出，提示改選三樓；一樓超過 50 人不能送出。
- 當天實到人數超過：三樓 40 人以下補到下一級差額，41 人以上每多一人補 NT$500。
- 私人活動可選一樓、二樓交誼廳、三樓；4F 從會員建立流程移除。
- 三樓不設硬上限；超過 60 人時提示「需言文字確認場地容量」，由審核把關（KK 08:42 同意）。
- 一樓包場：至多 50 人；不避開營業時段，任何時段都可申請；30,000 可全額折抵當場餐飲（含酒水、不折現）。一樓包場當天停止對外營業，審核通過時要同步通知店長排班，並關閉該時段的訂位（POS「不可訂位設定」）。
- 時段與超時費：1 時段＝2 小時（沿用母檔）；超時每小時 一樓 NT$10,000（KK 08:46）、二樓交誼廳 NT$3,000（沿用母檔）、三樓依人數級距（KK 08:51）：1–10 人 2,000／11–20 人 3,000／21–30 人 4,000／31–40 人 5,000／41 人以上 6,000。三樓超時費依序對應場地費的五個人數級距。
- 取代現行私人活動訂金 NT$1,000（`lib/event-applications.js` `PRIVATE_EVENT_DEPOSIT_TWD`）。

### 4.7 代收金流手續費與撥款（KK 2026-10-22 定案）

- 10% 是**代收金流手續費**：言文字代收票款，Stripe 刷卡費由言文字從這 10% 支付，不另向主辦人收。
- 計算：撥款＝（票價實收 − 已退款）× 90%。場地茶飲費、逐活動稅金不列入基數。
- 撥款日：活動結束日隔天起算第 10 個工作日（工作日依人事行政總處行事曆）。
- 撥款後才發生的退款，從主辦人下一場活動的撥款扣回；沒有下一場就請主辦人退回。
- 主辦人要先在 App 填撥款帳戶（戶名、銀行代碼、帳號）才能開賣付費票；完整帳號只有平台管理員看得到。
- 活動結束時，系統自動建立 `event_settlements` 待撥款紀錄（scheduled，`due_on`＝撥款日）；**實際匯款由 Admin 人工執行後登錄**，系統不自動轉帳。
- 主辦人在 App 看得到：票款、退款、手續費、預計撥款日、撥款狀態。

### 4.8 取消與退費規則（參考 ACCUPASS 與台灣場地主流規則）

參考來源（2026-10-22 查閱）：
- ACCUPASS 退票規則：付費票在活動開始前 8 日前可申請退票，酌收票價 10% 退票手續費；非消費者因素的退費手續費由主辦方負擔。https://accupass.uservoice.com/knowledgebase/articles/128433 、https://accupass.uservoice.com/knowledgebase/articles/198235
- 臺北市婦女館：14 日前全退、8–13 日退 50%、7 日內不退；天災停電全退。https://www.ywca-taipei.org.tw/tpewomen/upload/Image_202603301400.pdf
- 活活聚落：30 日前全退、30–7 日退 50%、7 日內不退；不可抗力全退。https://www.esliving.org/rentalrules
- 典空間：30 日以上全退、14–29 日退 50%、不到 14 日不退。https://idea-plan-space.com.tw/term

**A. 私人活動場地費（主辦人取消）**

| 取消時間（不含活動當日） | 退費 |
|---|---|
| 審核未通過 | 全額退還 |
| 活動日 14 日前 | 全額退還 |
| 活動日前 8–13 日 | 退 50% |
| 活動日前 7 日內 | 不退費 |
| 颱風等經政府公告停班停課、言文字因素無法使用場地 | 全額退還或免費改期 |

- 改期：活動日 7 日前可申請一次，限 3 個月內的日期，不收費；改期後再取消，依原活動日計算退費。
- 退款退回原付款卡，由 Admin 執行。

**B. 參加者退票（言文字售票）**

- 主辦人在建立活動時二選一，**開賣後不能改**：
  - 「接受退票」（預設）：活動開始前 8 日前，參加者可在 App 自行退票，扣票價 10% 手續費後退回，名額自動釋出。
  - 「不接受退票」：參加者不能自行退票，但可以轉票給別人（現有轉票功能）。
- 場地茶飲費 NT$150 在可退票期間全額退還，不扣手續費。
- 退票扣下的 10% 手續費歸言文字（同代收金流手續費），該張票不計入主辦人撥款。

**C. 主辦人取消公開活動**

- 已付款的參加者一律全額退款，含票價與場地茶飲費（非消費者因素，不向參加者收手續費）。
- 已發生的金流手續費由主辦人負擔：活動前 8 日前取消，免收；活動前 7 日內取消，按已售票款的 10% 從主辦人之後的撥款扣除，沒有後續撥款就請主辦人支付。
- 颱風停班停課等不可抗力：全額退款，不向主辦人收費，可改期一次。
- 取消後系統自動通知所有參加者（現有取消通知功能）。

**D. 言文字取消（場地因素）**：全部全額退款，不收任何費用。

**E. 外部售票的活動**：參加者退票依外部平台規則，言文字不處理；主辦人已預付的場地茶飲費比照 A 表退費。

## 5. 例外與邊界狀態

| 情境 | 行為 |
|---|---|
| 官網帶 `unlock_code` 進 App | App 自動選好隱藏票；碼錯就顯示「解鎖碼不正確」，不洩漏票種存在 |
| 已寄出的舊邀請信 | 走官網轉址到 App，`#invite` 不遺失（hash 需由前端轉址，伺服器看不到） |
| Stripe 付款中關掉 App | 現有 webhook／reconcile 仍會核銷；下次開 App 從「我的報名」看到狀態 |
| 未登入報名後才登入 | 以 Email 對應同一帳號，報名自動出現在「我的報名」（後端已是此行為） |
| 第三方網站嵌入 | 嵌入視窗改載 App 的 `/e/<slug>?embed=1`；App 需允許被 iframe（調整該路徑的 `frame-ancestors`） |
| 主辦人送出上架後又修改 | 依決策 1：已公開的活動，修改名稱、時間、地點時要確認，系統會通知已報名者 |
| 被移出主辦團隊 | App 主辦頁回 404 → 移除該活動卡片並提示 |
| 管理員在 Admin 強制下架 | App 主辦頁顯示「已被言文字下架」與原因，主辦人不能自行重新上架 |
| 離線 | 可看已載入的票券 QR；報名與主辦操作要連線，不假裝成功 |
| 已有有效報名後想從言文字售票改外部 | 不允許直接切換；要先取消活動或處理退款（限 Admin），避免已付款者失去票券 |
| 外部改言文字售票 | 允許；外部平台既有的報名者不會自動帶入，提示主辦人可匯入名單 |
| 外部報名網址失效（404） | 每日檢查一次，失效時通知主辦人，官網報名按鈕改顯示「報名連結暫時無法使用」 |
| 匯入網址抓不到資料、被擋或逾時 | 顯示「這個網站無法自動讀取，請手動填寫」，網址仍帶入報名網址欄位 |
| 匯入的時間沒有時區 | 預設台北時間，並在欄位旁提示「請確認時間」 |

## 6. 手機優先與可及性要求

- 以 390×844 為主要尺寸，320px 寬不橫向捲動；主按鈕固定在底部並避開 `safe-area-inset-bottom`。
- 點擊目標 ≥ 44×44px，欄位字級 ≥ 16px；使用正確的 `type`／`inputmode`。
- 欄位有可見 label；送出錯誤時捲到第一個錯誤欄位並 focus。
- 中英日三語沿用 `m.html` 字典；支援 200% 字級、`prefers-reduced-motion`。
- 活動文案不寫樓層字樣（`publicText` 會改寫）。

## 8. 驗收條件
