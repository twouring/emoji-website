# 三品牌後台重規劃（平板操作版）

- 日期：2026-10-11
- 範圍：言文字工作區、在咖啡、三點水、等等空間三個品牌後台
- 目標：讓三個品牌可獨立日常營運，言文字管理員可統一治理；現場以平板可操作為基準。

## 規劃結論

現有後台不需要拆成三套系統；維持同一個 `/admin`，用「工作區」切分：

1. **言文字品牌後台**：可存取所有品牌與全站治理功能，包含會員、金流、網站內容、行銷、權限、系統設定與操作紀錄。
2. **在咖啡品牌後台（CAFE）**：只允許在咖啡對應人員存取，只處理在咖啡菜單與出餐。
3. **三點水品牌後台（BAR）**：只允許三點水對應人員存取，只處理三點水菜單與出餐。
4. **等等空間品牌後台（SPACE）**：只允許等等空間對應人員存取，處理活動、行事曆、場地申請、櫃檯會籍與點數。

共用品牌帳號可在頂欄直接切換所有品牌；品牌子帳號只會看到授權品牌，不會出現其他品牌入口。

## 平板操作原則

後台以 10–11 吋平板、站立或櫃檯操作為基準：

- 主要按鈕、分頁、表單欄位觸控高度不低於 **48px**。
- 860px 以下導覽改成上方橫向工作列，不使用窄側欄。
- 表格不壓縮中文字，統一用水平滑動，避免欄位擠成直排。
- 表單欄位在窄版改為單欄，減少誤觸。
- 出餐、清桌、活動簽到、櫃檯開通等高頻操作優先保留在第一層。

## 工作區與功能矩陣

| 工作區 | 使用者 | 主要任務 | 可用分頁 | 不可做的事 |
|---|---|---|---|---|
| 言文字品牌後台 | 言文字管理者 | 全品牌治理、會員、活動、內容、行銷、權限 | 總覽、會員、參與紀錄、活動、行事曆、櫃檯、最新消息、社群、廣告、權限、系統、操作紀錄，且可切換到所有品牌工作區 | 無，依超管／一般管理員再分系統權限 |
| 在咖啡 | 咖啡現場人員 | 櫃檯收款、出餐、訂位、日結、估清、菜單、桌號 QR | 櫃檯結帳、點餐出餐、訂位、日結報表、菜單 | 看會員個資、活動名單、三點水菜單／訂單、系統設定、強制清混桌 |
| 三點水 | 餐酒現場人員 | 櫃檯收款、出餐、訂位、日結、估清、菜單、桌號 QR | 櫃檯結帳、點餐出餐、訂位、日結報表、菜單 | 看會員個資、活動名單、在咖啡菜單／訂單、系統設定、強制清混桌 |
| 等等空間 | 空間營運人員 | 活動審核、行事曆、現場開通會籍、發點 | 活動、行事曆、櫃檯 | 改餐飲菜單、處理餐飲訂單、系統設定 |

## 資料隔離規則

### 餐飲品牌

- `users.admin_brand = CAFE`：只能看與操作 CAFE 品項、訂單。
- `users.admin_brand = BAR`：只能看與操作 BAR 品項、訂單。
- 菜單儲存時，品牌子帳號不得修改其他品牌品項。
- 出餐單狀態更新前，後端會確認該訂單包含該品牌品項；非授權品牌回 `404`。
- 清桌前，後端會確認該桌沒有混合其他品牌品項；混桌須由言文字管理員處理，避免某品牌誤關掉另一品牌訂單。

### 等等空間

- `users.admin_brand = SPACE`：可處理活動、場地申請、行事曆、櫃檯會籍與點數。
- 活動主辦人不是全站管理員；只從單場活動的「主辦團隊」授權。
- 活動與報名資料維持單場隔離。

## 每日操作流程

### 在咖啡／三點水

1. 平板開 `/admin`，用品牌子帳號登入。
2. **開店**：進「點餐出餐」確認「暫停點餐」是關的；進「菜單」把今天沒進貨的品項按「今日估清」（翌日 03:00 自動恢復）。
3. **客人點餐**：客人掃桌上 QR 自己加菜（目前不開線上刷卡，用餐完到櫃檯結）。
4. **櫃檯結帳**：進「櫃檯結帳」點桌號 → 看未結帳品項 → 選現金／刷卡／LINE Pay／轉帳 → 需要時勾「會員價」或勾選部分品項分帳 → 「收款並送出餐單」。櫃檯也能代客加菜、逐項作廢（要填原因）。
5. **出餐**：「點餐出餐」每 10 秒更新、有新單會響；品項前標菜單類別（開放式餐吧不分吧檯／廚房），可列印小票；按「出餐並通知」推播給客人到櫃檯取餐，再按「已取餐」。
6. **訂位**：客人線上訂位送出即成立並收到確認信；進「訂位」看今天／本週名單、填桌號，客滿或臨時狀況按「取消」（寄婉拒信），當天按「已到」／「未到」。
7. **最後點餐／包場**：「點餐出餐」勾「暫停點餐」並填文案，客人掃碼就會看到、無法加菜；恢復時取消勾選。
8. **清桌**：這桌全部結清才按「清桌」；有未結帳品項系統會擋，請先結帳或逐項作廢（只有言文字管理員能強制清桌）。
9. **打烊**：進「日結報表」看營收、付款方式、品項銷量、時段分布；「匯出 CSV」交會計。作廢單另列、不計營收。
10. **作廢**：結錯的單在「點餐出餐」或「櫃檯結帳」按「作廢」填原因，品項會退回該桌未結帳；只能作廢當個營業日、線上刷卡的要先在 TapPay 退款。

### 等等空間

1. 平板開 `/admin`。
2. 用 SPACE 子帳號登入。
3. 進「行事曆」看今日／本週活動與申請。
4. 進「活動」審核場地申請、管理名單、簽到、通知。
5. 進「櫃檯」處理現場會籍開通與點數發放。

### 言文字管理員

1. 進「總覽」看今日待辦。
2. 需要時用頂欄品牌列切到各品牌檢查現場狀態。
3. 進「權限管理」授權或取消品牌子帳號。
4. 重大內容、系統、行銷、操作紀錄仍留在言文字工作區。

## 餐飲營運功能（2026-10-11 第二批）

以在咖啡／三點水現場人員視角補齊開店到打烊的閉環：

| 功能 | 位置 | 說明 | API |
|---|---|---|---|
| 櫃檯結帳（POS） | 櫃檯結帳 | 桌況格 → 未結帳品項 → 現金／刷卡／LINE Pay／轉帳 → 會員價 → 分帳 → 收款即成出餐單；代客加菜、逐項作廢 | `POST /api/admin/orders/sessions/:id/checkout`、`/items`、`DELETE …/items/:line` |
| 桌況一覽 | 櫃檯結帳 | 每桌：點餐中／準備中／可取餐／待清桌、未結金額、混桌提示；15 秒更新 | `GET /api/admin/orders`（`sessions[].state`） |
| 估清／今日售完 | 菜單 | 一鍵估清，客人端立刻點不到；以營業日記錄，翌日 03:00 自動恢復 | `POST /api/admin/menu/sold-out` |
| 暫停點餐 | 點餐出餐 | 依店別開關＋客人文案（最後點餐、包場、公休）；客人加菜回 423 | `POST /api/admin/orders/pause`、`GET /api/orders/pause` |
| 訂位管理 | 訂位 | 依日期列表（線上訂位送出即成立）、排桌、店內留言、取消寄婉拒信、已到／未到 | `GET /api/admin/reservations`、`POST …/:id/status` |
| 日結報表 | 日結報表 | 營業日（03:00 起算）營收、付款方式、時段、品項銷量、作廢；CSV 每品項一列 | `GET /api/admin/sales` |
| 作廢／稽核 | 點餐出餐、櫃檯結帳 | 作廢整張單須填原因，品項退回未結；記 `void_reason/voided_by/voided_at` 與操作紀錄 | `POST /api/admin/orders/:id/void` |
| 品項標類別 | 點餐出餐 | 開放式餐吧不分吧檯／廚房；每個品項前標菜單類別（咖啡、日式主食…），出餐單依類別分段 | `orders[].items[].cat`（API 仍附 `stations`，前端攤平） |
| 出餐小票列印 | 點餐出餐、櫃檯結帳 | 72mm 版面：桌號、時間、付款、分站品項、合計 | 前端 |
| 清桌防漏收 | 櫃檯結帳 | 有未結帳品項回 409；只有言文字管理員可 `force` | `POST /api/admin/orders/sessions/:id/close` |
| 特餐排程 | 菜單 | 品項「供應起／迄」日期，期間外客人點不到 | `available_from/available_to` |
| 會員價 | 櫃檯結帳 | 勾選後以菜單會員價（`emo`）重算，只有設了且較低的品項會變 | `checkout.member` |

未做（以文件／外部工具處理）：庫存成本（估清快速鍵足以應付初期）、班表交班（用 Google 日曆）、客訴備註（訂位有店內留言、作廢有原因欄）。

## 平板 POS 獨立子站（2026-10-11 第三批）

現場人員不進 `/admin`，改用 `pos.emoji.tw`（純瀏覽器，iPad 用 Star webPRNT Browser 開啟）：

| 項目 | 做法 |
|---|---|
| 網址 | `https://pos.emoji.tw` → `/pos`；分頁 `/pos`（結帳）、`/pos/orders`（出餐）、`/pos/soldout`（估清）、`/pos/reservations`（訂位）、`/pos/sales`（日結）。`www.emoji.tw/pos` 同樣可用 |
| 部署 | 同一支 Express，依 host（`POS_HOSTS`，預設 `pos.emoji.tw`）把首頁與 `/admin` 轉到 `/pos`；DNS 把 `pos` CNAME 到與 `www` 相同的 Zeabur 服務並在 Zeabur 加這個網域即可，不需第二個服務 |
| 帳號 | 與 `/admin` 同一組（Google 或 Email）。言文字管理員可切在咖啡／三點水／全部；品牌子帳號只看自己的店；等等空間子帳號擋在 POS 外 |
| 登入 | Google callback 綁在 `www`，所以子網域的登入鈕先到 `www.emoji.tw/auth/google?redirect=https://pos.emoji.tw/pos`，完成後以 `#token` 導回；`WEB_ORIGINS` 預設已含 `https://pos.emoji.tw` |
| 共用程式 | 餐飲營運畫面（出餐看板、櫃檯結帳、訂位、日結、估清）從 `admin.html` 抽到 `public/pos-ops.js`／`pos-ops.css`，後台與 POS 共用；宿主頁各自提供 `api/esc/toast/opsHref…` |
| 估清分頁 | POS 新增「估清」：大格子點一下切換今日估清（只動 `sold_out`，翌日 03:00 自動恢復），不用進菜單表格 |
| 純瀏覽器 | 不做 PWA（無 manifest、無 service worker）；iPad 以 USB-C 接 mPOP，用 Star webPRNT Browser 開 `https://pos.emoji.tw/pos`。頁面載入時會註銷舊版殘留的 service worker 並清掉 `pos-v*` 快取 |
| 穩定性 | 平板 Wi-Fi 閃斷時，出餐看板與結帳頁更新失敗只 toast、不清空畫面，並維持 10／15 秒輪詢 |

安裝步驟（每台平板一次）：開 `https://pos.emoji.tw` → 登入 → 「加入主畫面」→ 之後從主畫面圖示開啟。

## 後續建議

1. **品牌首頁卡片**：在每個品牌工作區首頁顯示今日待辦、未出餐、今日活動、需審核事項。
2. **平板實機驗收**：用 iPad 直式與橫式各走一次：登入、切工作區、櫃檯收款、出餐、估清、訂位確認、日結匯出、活動簽到、櫃檯發點。
3. **權限稽核**：正式上線前用三個子帳號各測一次 API 403／404 邊界，避免只驗 UI。
4. **列印**：若要接熱感應印表機，把小票版面改成 ESC/POS 或用瀏覽器 kiosk 列印。
